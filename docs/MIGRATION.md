모든 적재가 자연키 기준 UPSERT 라, 중간에 실패하면 그냥 처음부터 다시 실행하면 됩니다.

## 준비

1. [DEPLOY.md](DEPLOY.md) 1~6단계를 끝내 새 백엔드가 떠 있어야 합니다.
2. 기존 Apps Script 를 한 번 **다시 배포**해야 합니다.
   `gas/Code.gs` 에 이관용 `exportAll` 액션이 추가됐기 때문입니다.
   - script.google.com → 해당 프로젝트 → `gas/Code.gs` 내용을 붙여넣기
   - **배포 > 배포 관리 > 편집(연필) > 버전: 새 버전 > 배포**
     (기존 배포를 수정하면 웹앱 주소가 그대로 유지됩니다)

## 실행

`tools/migrate.html` 을 브라우저로 엽니다.
GitHub Pages 로 올렸다면 `https://<페이지주소>/tools/migrate.html`.

1. **관리자 로그인** — Google 계정으로 로그인. 시트와 새 DB 양쪽 모두 관리자여야 합니다.
2. **주소 확인** — Apps Script 웹앱 주소(`.../exec`)와 새 백엔드 주소를 넣습니다.
3. **시트에서 가져오기** — 시트를 읽기만 합니다. 아래에 건수가 표시됩니다.
4. **시험 실행** — 아무것도 쓰지 않고, 넣을 건수와 문제 있는 행만 보여줍니다.
5. **실제로 넣기** — 진짜로 적재합니다.

Apps Script 가 CORS 등으로 응답하지 않으면, 3단계의 *JSON 직접 붙여넣기* 를 쓰세요.
Apps Script 편집기에서 `exportAll()` 함수를 실행하고 로그의 JSON 을 복사해 붙여넣으면 됩니다.

## 옮겨지는 것

| 시트 탭 | 새 표 | 비고 |
|---|---|---|
| `강사` | `instructors` | 이름 기준. 순서는 `sort_order` |
| `근무불가일` | `unavailable` | (이름, 날짜) 자연키 |
| `제출현황` | `submissions` | (월, 이름) 자연키. 시트의 `TRUE` 문자열도 인식 |
| `일정` | `assignments` | `id` 유지. 폐지된 `carry` 값도 보존 |
| `교체요청` | `swaps` | 진행 중·완료 요청 모두 |
| `학생프로그램` | `programs` | 기간(시작일~종료일) 그대로 |
| `설정` 의 `weeklyCap` | `settings` | 단가(`rate.*`)는 폐지되어 버려집니다 |
| `설정` 의 `holiday.YYYY-MM-DD` | `holidays` | 각자 행으로 분리 |
| `설정` 의 `publish.YYYY-MM` | `months` | |
| `설정` 의 `admin.whitelist` | `admins` | 쉼표 목록을 행으로 분리 |

옮기지 않는 것:

- `순번시드` 탭 — 순번 추천 기능이 폐지되어 대응 표가 없습니다.
- `이월` 탭 — 이월 기능이 폐지되어 대응 표가 없습니다.
  다만 **`일정` 탭의 `연구이월` / `지원이월` 행은 시수가 사라지지 않도록 그대로 옮겨집니다.**
  집계에서는 평범한 연구·지원 시수로 잡힙니다.

기록이 필요하면 시트 자체를 보관하세요. 이관은 시트를 읽기만 하고 고치지 않습니다.

## 문제가 있는 행

날짜 형식이 깨졌거나 알 수 없는 유형이 든 행은 **건너뛰고 나머지는 넣습니다.**
건너뛴 행은 진행 기록에 이유와 함께 표시되니, 확인 후 시트를 고쳐 다시 실행하세요.

## 끝나고

1. 앱을 열어 지난 달들이 제대로 보이는지 확인합니다.
2. 백업을 하나 떠 둡니다.
   ```bash
   cd worker && npx wrangler d1 export swteacher-db --remote --output backup.sql
   ```
3. 확인이 끝나면 Apps Script 배포를 해제해도 됩니다. 시트 자체는 남겨두길 권합니다.
